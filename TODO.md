## 1. Omarchy support (`wallpaperctl setup omarchy` + dynamic theme)

**Status: implemented + live-tested on this machine (theme active, picker verified).**

**Design decisions (confirmed):**
- One persistent user theme: slug `dynamic-wallpapers` → displays as **"Dynamic Wallpapers"**.
  Never create a theme per wallpaper set.
- Activation gate = Omarchy's current theme (`~/.local/state/omarchy/current/theme.name`);
  when it is `dynamic-wallpapers`, wallpaperctl drives wallpapers **and** colors.
- When another theme is active: wallpaperctl still sets the background via omarchy
  (bg-only mode); colors are not touched.
- Per-wallpaper retint = **full `omarchy theme refresh`** (official tooling; terminals hot-reload).
- Palette source: wallust (`~/.cache/wal/colors.json`, post contrast-fix) → omarchy
  `colors.toml`. Accent via existing `pick_accent()` strategy.
- Animated wallpapers: use **omarchy motion-wallpaper** (`omarchy-shell motion-wallpaper
  play/stop` + theme `wallpaper-video.<ext>` staging), not mpvpaper, when omarchy owns the
  background. mpvpaper stays as fallback only if omarchy path fails.
- No new dependencies. Use `util.run`/`have`; soft failures everywhere.

### Omarchy machinery facts (researched, for reference)
- Themes: `/usr/share/omarchy/themes/<name>` (official) + `~/.config/omarchy/themes/<slug>` (user overlay).
- `omarchy theme set <name>`: stages theme → `~/.local/state/omarchy/current/theme`,
  renders app configs from `colors.toml` + `*.tpl` (`/usr/share/omarchy/default/themed/`,
  `~/.config/omarchy/themed/`), picks background from theme `backgrounds/`
  (or `OMARCHY_THEME_SKIP_BACKGROUND=1`), retints apps in parallel, fires `theme-set` hooks.
- `omarchy theme refresh` = same with skip-background (retint only, keeps background).
- `omarchy theme bg set <path>` = background-only switch (symlink + shell IPC).
- `omarchy-theme-color` derives almost all keys from `background`/`foreground`/`color0..15`;
  **`accent` has no derivation** → generator must always emit it. Value charset is restricted.
- Omarchy does NOT run hyprpaper; omarchy-shell (quickshell) draws the background.
- kitty/btop consume omarchy-staged configs (include/symlink) → no conflict with wallust
  templates (starship, rofi, opencode, … stay wallust-managed).
- The theme switcher picker lists themes **from its preview cache** — a theme without
  `preview.png` is invisible. Setup always renders one (palette swatch fallback) and warms
  the cache with `omarchy theme switcher --preload`.
- `omarchy theme set`/`refresh` retint churn (terminal reload signals, hyprctl reload)
  interrupts running TUI agents (known Omarchy annoyance) → mitigations below.

## 2. `install.sh` (pipx bootstrap installer)

**Design decisions (confirmed):** POSIX sh (Linux + BSDs); bootstrap-only — installs
Python/pipx and the package, then delegates ALL system/theme deps to
`wallpaperctl setup all` / `setup install` / `setup omarchy` (AUR handled there via
paru/yay). Auto-run `setup all` after install (failure is soft).

- [x] Create `install.sh` (`#!/bin/sh`, `set -eu`, no bashisms; shellcheck clean):
  - flags: `--upgrade` (→ `pipx install --force`), `--from <path|git-url>`,

  - prereqs: Python ≥ 3.10 check; pipx missing → offer install via package manager
    (apt/dnf/zypper/pacman(`python-pipx`)/pkg/pkg_add/brew, sudo→doas elevation),
    prompt unless `--yes`; fallback hint `pip install --user pipx`

    `$0` check handles piped invocation)

  - verify `wallpaperctl --version`; PATH hint + `pipx ensurepath` offer
  - auto-run `wallpaperctl setup all` (with `-y` when `--yes`); soft-fail with re-run
    instructions; prints follow-ups incl. `setup omarchy` when omarchy detected
